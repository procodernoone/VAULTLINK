      How peer-to-peer file transfer works in Vaultlink

      1. Exchange two codes One person creates an invite code and sends it through any chat app. The other pastes it and sends a reply code back.
      2. Browsers connect directly Once both codes are in, the two browsers open a WebRTC data channel to each other. No relay is involved on most networks.
      3. Drop files, they download Files are sent in small chunks over the encrypted channel and saved to disk automatically on the receiving side.

      Why use Vaultlink to send files

      Direct transfer

      Bytes move from your browser to theirs. There is no upload step and no download link to share.

      Encrypted end to end

      WebRTC encrypts every data channel with DTLS. With no server in the middle, only the two peers can read the data.

      No account, no server

      Signaling is manual copy and paste. Vaultlink runs as static files with nothing to sign up for.

      Works in modern browsers

      Chrome, Firefox, Safari, and Edge on desktop and mobile, with no extension or install.

      Built for large files

      Chunked sending with backpressure keeps the page responsive while big files move across the channel.

      Free and open source

      Plain HTML, CSS, and JavaScript. No framework, no build step, no tracking.

      Frequently asked questions

      Are my files really end-to-end encrypted?

      Yes. WebRTC data channels are encrypted with DTLS between the two browsers, and Vaultlink has no server that handles your files. The invite and reply codes carry the connection details, so share them only with the person you intend to connect to.

      Do my files go through a server?

      No. Files travel directly between the two browsers. Public STUN servers are used only to help each browser learn its public address, and they never see file data or your codes.

      Is there a file size limit?

      Vaultlink sets no limit. The receiving browser holds the file in memory until the transfer completes, so very large files are limited by the receiver's available RAM.

      Why do I have to copy and paste codes?

      Two browsers cannot find each other without exchanging connection details first. Most tools use a signaling server for that. Vaultlink skips the server, so you pass the codes through any chat app instead.

      Why does it not work when I open the file from my computer?

      WebRTC requires a secure context. Open Vaultlink from https:// or http://localhost, not from a file:// address.

      The connection failed. What now?

      Some corporate firewalls and mobile networks block direct peer-to-peer paths. In that case a TURN relay is needed. Try a different network, or add a TURN server to the app configuration.

      Does Vaultlink work on mobile?

      Yes, on current mobile browsers. Keep the screen awake and the tab in the foreground during a transfer, and avoid very large files on low-memory phones.
